# 项目记忆文档 — aiagents-stock

> 本文件供 AI 助手(Claude Code)与开发者快速识别项目全貌。由 2026-09-01 全项目梳理生成,修改架构后请同步更新。

## 1. 项目速览

**复合多 AI 智能体 A 股分析系统**。上游开源项目(README 作者:山东科技大学 于舒馨),本机部署的是定制 fork(remote `stock2` = git@github.com:zdsy-aa/aiagents-stock2.git),在主线之上本地演进出:缠论选股、六脉神剑、起涨预测(GBDT)、新闻流量监测、产业链分析、智能盯盘(miniQMT)、PostgreSQL 数据仓库(pg-warehouse)、TDX 本地行情等模块。

- **技术栈**:Python 3.12 + Streamlit(UI)+ SQLite(业务库)+ PostgreSQL 16(仓库)+ Go(tdx-api 行情网关)+ LightGBM(起涨预测)+ OpenAI SDK(任意 OpenAI 兼容 LLM,默认 deepseek-chat)
- **部署**:8 容器 docker-compose(`agentsstock-network` 网络,统一 json-file 日志 rotation 10m×3)
- **主入口**:http://<host>:8503(Streamlit);辅助:8080(TDX 行情)、8088(AKTools)、5432(PG)
- **代码规范**:用户面向输出用中文;分析报告存 `/home/tdxback/report/` 并加 `_YYYYMMDD_HHMMSS` 后缀;只在 `main` 分支开发(见 CLAUDE.md)

## 3. 代码地图(按层)

**入口/UI 层**
- `app.py` — Streamlit 入口:主题注入 → load_dotenv → `render_top_nav()` → `route_page()`
- `views/page_router.py` — 路由 = session_state 的 `show_*` 布尔标志分派(无框架路由)
- `views/nav_model.py` — 导航单一数据源 `NAV = [(大类,图标,[(子页,show_flag,help)])]`,共 5 大类
- `views/top_nav.py` / `sidebar.py` — 顶层大类按钮 + 子页 segmented control / 侧栏
- `views/analysis_runner.py` — 统一个股分析函数 `analyze_single_stock_for_batch`(所有策略必须走它,禁直接调 ai_agents)
- 各 `*_ui.py` 均在项目根目录,导出 `display_xxx()`。**新增页面三步**:写 ui → nav_model.py 加条目 → page_router.py 加 `if st.session_state.get('show_xxx'): ... return True`(放在"缠论"标志之后)
- mindmap_ui.py — 「🧠 项目思维导图」页(markmap 渲染,60s 自动刷新,读 data/mindmap 产物)

**运维工具**
- `tools/mindmap_generator.py` — 项目思维导图生成器(纯 stdlib):宿主机 cron 每分钟扫描仓库,快照对比有变更才重建,产物 `data/mindmap/project_map.md`+`meta.json` 挂载进容器;meta.node_count 含逻辑分组节点
- `tools/mindmap_annotations.json` — 导图注解(文件说明+逻辑分组),手工维护

**数据层**
- `akshare_gateway.py` — 网关核心(42KB):五级降级链 `本地SQLite库 → TDX(8080) → AKTools(8088) → 本地akshare → Tushare`,统一入口 `akshare_gw.call()`;含 CircuitBreaker(3次失败熔断300s)、RateLimiter(1次/s)、DataCache(内存500条,CACHE_TTL 按类别 10s~3600s);`BLOCKED_EM_FUNCS` 为东财被封接口清单(短超时)
- `data_source_manager.py` — `DataSourceManager` 单例,业务侧数据门面(历史K线/基本信息/财务/实时)
- `stock_data.py` — `StockDataFetcher`:技术指标计算(MA/RSI/MACD/KDJ 等)+港美股直连
- `config.py` / `config_manager.py` — 配置体系(.env 读取 / UI 读写 .env)
- `database.py` — `StockAnalysisDatabase`,analysis_records 表(JSON 存分析结果)
- `base_db.py` — `BaseDatabase`:SQLite 连接工厂(WAL、busy_timeout=30s),`DATA_DIR` 可用 `AIAGENTS_DATA_DIR` 覆盖
- `base_scheduler.py` — `BaseScheduler`:后台线程原语(running 标志+schedule.run_pending+异常不杀线程),被 4 个 scheduler 继承
- `tdx-api/` — Go 通达信协议行情服务:落本地 SQLite(`tdx-data/database/kline/*.db`,每票一库,10 种周期表)
- `pg_warehouse/` — PG 仓库脚本:DDL + import_all.py(全量,DROP 重建)+ sync_daily.py(增量:有 id 主键按 max(id),无 id 表 TRUNCATE 全量)

**LLM 层**
- `deepseek_client.py` — `DeepSeekClient`:OpenAI SDK 封装,60s 超时+3 次指数退避;内置各分析师专用 prompt;`final_decision` 提取 JSON
- `ai_agents.py` — `StockAnalysisAgents`:5 分析师(技术/基本面/资金面/风险管理/市场情绪)并行(ThreadPoolExecutor 6 线程)+ 首席分析师汇总讨论
- `model_config.py` — 17 个预置模型(deepseek/通义/硅基流动免费模型)

## 4. 数据架构

**数据流**:TDX 协议 → tdx-api(Go,8080)落本地 SQLite → 网关第 0 级读本地库(或 AKTools/akshare/Tushare 直取)→ `akshare_gw.call` 内存缓存 → 业务引擎 → 各业务 SQLite(`data/*.db`)→ UI 只读展示;每晚 21:00 增量同步进 PostgreSQL 供跨表 SQL。

**SQLite 业务库清单**(data/ 下 13 个):chanlun_signals.db、liumai_signals.db、combo_signals.db、qizhang_picks.db、longhubang.db、low_price_bull_monitor.db、main_force_batch.db、news_flow.db、portfolio_stocks.db、profit_growth_monitor.db、sector_strategy.db、smart_monitor.db、stock_monitor.db、stock_analysis.db。

**PostgreSQL**:schema `market` 5 表(stock_codes、trade_calendar、kline_day、kline_5min、kline_30min);schema `signals` 44 表(业务信号库按前缀平铺,如 news_flow_*12 表)。唯一索引 (code,ts)。

**单位/时区(高频坑)**:
- 本地库与 TDX 价格均 ×1000 整数,网关统一 ÷1000 转元;**但成交额未 ÷1000**(gateway L276/L378),PG 里 amount 又 ÷1000(convert.py),口径不一致
- K 线 Date = Unix 秒(UTC),读时 +8h 转 Asia/Shanghai;PG 增量在 SQL 内算 EPOCH 避免 Python 时区错 8h
- kline 目录存在 `000001.db` 与 `sz000001.db` 重复票文件;codes.db 与 kline 的 code 标识体系不同(000001 一指上证指数一指平安银行),不能 JOIN
- 信号库 TIMESTAMP 字段实为 TEXT 本地时间串,PG 侧走 to_tstamp_str 转换

## 6. AI 分析统一规范(重要)

- **个股分析必须走** `views.analysis_runner.analyze_single_stock_for_batch`(内部调 StockAnalysisEngine),**禁止直接调 ai_agents**(docs/UNIFIED_ANALYSIS_SPEC.md)
- `final_decision` 标准字段:`rating / confidence_level / entry_range / take_profit / stop_loss / target_price / advice`(旧字段 `investment_rating/confidence/entry_exit_positions` 已废弃)
- 用户可配 `enabled_analysts_config`(选分析师)、`selected_model`(换模型)
- LLM 用 OpenAI SDK,base_url 必须带 `/v1`;prompt 字段约定是 DeepSeek 风格

## 7. 调度体系

**容器内**(schedule 库,base_scheduler 基类):智能盯盘/持仓/新闻流量/智策 4 个 scheduler 线程,随主应用运行。

**宿主机 cron(crontab -l 实况)**:
| 时间 | 脚本 | 作用 |
|---|---|---|
| 21:00 每天 | ops/daily_watchlist_and_mail.sh | docker exec 跑 data/profit_mining/daily_watchlist.py → export md/xlsx 到 ~/report/ → push_watchlist.py 发邮件 |
| 17:30 周一~五 | ops/sector_strategy_and_mail.sh | docker exec 调 sector_strategy_scheduler._run_analysis() 后发邮件(脱离 Streamlit 内存态) |
| 08:00 每天 | ops/check-cron.sh | 只读健康检核(磁盘/内存/代理/容器/端口),写 check-latest.log,失败发邮件 |
| 03:00 周日 | ~/docker-prune.sh | Docker 清理 |
| 每分钟 | tools/mindmap_generator.py | 快照对比,有变更才重建思维导图产物 data/mindmap/(页面 60s 刷新) |

注意:`ops/intraday_watchlist_and_mail.sh`(盘中选股,flock 锁+交易日门控)存在但**未登记 crontab**。21:00 邮件若早于 20:00 缠论重算会发"昨天"数据(已踩过坑,勿提前)。

## 11. 坑清单(速查)

1. 根目录代码改动需 `docker compose build agentsstock` 重建,否则不生效;./data 挂载即时生效
2. tdx-stock-web 启动 ~70s,start_period 90s 勿缩短;复用 app 镜像的 sidecar 必须 healthcheck disable
3. 缠论引擎是"简化缠论"(非标准定义),靠手工 K 线单测锚定,改算法前先跑 tests/test_chanlun_engine.py
4. 组合批处理依赖缠论先跑;盘中缠论写独立 intraday 库,勿与盘后库混淆
5. 第三方数据源(orz.ai、lhb-api.ws4.cn、问财)可能失效,各模块有降级链
6. sector/longhubang 多智能体串行调用耗时长;deepseek_client 默认 max_tokens 2000 偏小,各 agent 单独设
7. 网关"成交额"未 ÷1000 与价格口径不一致(见第 4 节)
8. `data/industry_chains/*.json` 是产业链配置真源;`strategy_catalog.py` 是策略清单真源
9. 思维导图产物在 data/mindmap/(不入库);改 tools/mindmap_annotations.json 后下分钟自动生效;改 mindmap_ui.py 需重建镜像
